# Chart style guide

What this style is: minimalist "editorial data journalism" — the register
used by the Financial Times, The Economist, Our World in Data, and (the
direct inspiration here) The European Correspondent. The goal is a chart
that reads as *reporting*, not as a default Excel/seaborn export: thin
marks, one reserved accent color, labels that sit next to the data instead
of in a legend box, and no chrome that isn't carrying information.

Every rule below exists because it fixes a specific way a "default" chart
looks unfinished. If you're adding a new chart function and unsure what to
do, match the closest existing example in this file rather than inventing
a new pattern.

## 1. Palette — four roles, not four colors

```
PRIMARY_COLOR  = "#4682b4"  # steelblue — the main/majority series, tested findings
ACCENT_COLOR   = "#c1440e"  # terracotta — RESERVED for risk/threshold/anomaly
NEUTRAL_COLOR  = "#9a9a92"  # gray — secondary/comparison series
INK_COLOR      = "#14171a"  # body text color; also descriptive/untested series
```

The rule that matters more than the hex values: **a color is a role, not a
decoration**. Terracotta means "this is the anomaly / the risk / the thing
that failed a check" *everywhere*, across every chart in a project. If you
need a fourth or fifth category, reach for `CATEGORICAL_PALETTE` (fixed
order, never auto-generated by the plotting library) before inventing a
new hue — a chart with 6 unrelated bright colors is the single most common
way a chart stops looking like this style.

One exception, worth naming explicitly: a chart explicitly marked
*descriptive, not statistically tested* may use `INK_COLOR` instead of
`PRIMARY_COLOR` for its single series — a visual signal that this one
hasn't been validated the way the blue charts have, not a random
inconsistency. Do this rarely and only when the chart's own docstring says
so.

## 2. Typography — three fonts, three jobs, never mixed

- **Sans (IBM Plex Sans)** — axis labels, tick labels, in-chart annotations,
  everything a reader parses as *data*.
- **Mono (IBM Plex Mono)** — source/footer lines, anything that reads as
  metadata rather than data.
- **Serif (IBM Plex Serif)** — **poster headlines only** (see §6). Never
  appears on an axis, tick, or in-article chart. A serif headline signals
  "this image is a standalone piece," which is exactly why it must not leak
  into charts that live inside an article's own HTML.

Register the bundled `fonts/*.ttf` via `chartstyle._register_fonts()`
(done automatically by `set_style()`) — don't rely on the font being
installed system-wide. This is the single highest-leverage fix for a chart
looking foreign next to the surrounding page: matplotlib silently falls
back to DejaVu Sans otherwise, and nobody notices until it's on a live page
next to real body text.

## 3. Background — one house default, one deliberate alternative

```
BG_WHITE = "#ffffff"   # default — matches most sites' own background, no seam
BG_CREAM = "#f8f6f0"   # warm-canvas editorial look (FT / European Correspondent)
```

Pick per **project**, not per chart — a page mixing white-background and
cream-background charts looks like a mistake, not a choice. Use white when
the chart embeds directly into a page that is itself white (avoids a
visible card/seam effect). Use cream for a project that wants the
warm-canvas editorial identity on its own page, or for output meant for a
context that expects a plain, deliberately "designed" figure (an academic
PDF, a poster). `set_style(bg="cream")` switches every chart drawn
afterward; flip it back with `set_style(bg="white")` — it's a one-line
decision, not a fork of the code.

## 4. Chrome — remove until it hurts

- No top/right spine, ever (`sns.despine(top=True, right=True)` — the
  seaborn default already does this).
- For a horizontal ranking/lollipop chart, also drop the left spine
  (`despine(left=True)`) — the category axis doesn't need a hard line, the
  labels alone carry it.
- Grid: one axis only (whichever carries the *value*, not the category),
  thin (`linewidth: 0.9`), colored to match the page's own rule/divider
  color (`GRID_ON_WHITE` / `GRID_ON_CREAM`) — never seaborn's default
  saturated gray. The grid should read as barely-there structure, not as a
  second data layer.
- No in-axes title (`ax.set_title(...)` / `plt.title(...)`) for an
  in-article chart — see §6.
- Legend: `frameon=False` always. Prefer direct labels (text placed at the
  end of a line/bar) over a legend box whenever there are ≤4 categories and
  room to place them — a legend forces the reader's eye to jump between a
  box and the data; a direct label doesn't.

## 5. Marks — thin, not default-thick

- **Single value per category → lollipop, not a bar.** A full-width bar's
  fill doesn't encode anything a thin line + dot doesn't already show; it
  just adds colored area to the page. Use `hlollipop()`.
- **Part-to-whole / composition (stacked) → keep a bar**, but thin it
  (`BAR_WIDTH = 0.5`, not seaborn's default ~0.8) and write the segment
  value inside the segment only if it's wide enough to hold the text
  legibly (skip the label rather than let it overflow — see
  `plot_region_totals` in the GeoGram project for the pattern: a threshold
  on segment width, total written in bold at the bar's end regardless of
  how thin the segments are).
- **Logistic regression against a binary outcome → binned-proportion view,
  not raw jittered 0/1 scatter.** Hundreds of overlapping points squashed
  onto two horizontal strips show density, not shape — `binned_logistic()`
  bins the x-axis, plots the observed share per bin (dot size ~ n) and the
  fitted curve with a 95% CI band instead.
- **Figure size scales with category count for horizontal charts** —
  `lollipop_height(n)`. Two charts on the same page showing 3 vs. 15
  categories at the *same* fixed height will look like different zoom
  levels next to each other even though each is individually correct; two
  charts meant to sit side by side (e.g. "count per group" and "% per
  group" for the same groups) should also share the same **width**, not
  just adaptive height.

## 6. In-article chart vs. poster — titles live in exactly one place

A chart that goes inside a real article's HTML **never** carries its
title/subtitle baked into the image. Reasons, in order of how often they
bite: a baked-in 18pt title becomes illegibly tiny on a phone when the
image scales to fit a narrow column; screen readers and search engines
can't read text inside a PNG/SVG shape; fixing a typo means re-running
Python instead of editing a line of HTML. The title/subtitle/source belong
in the page's own `<h2>`/`<figcaption>`, and the chart function should only
ever set `ax.set_xlabel()` / `ax.set_ylabel()` — no `ax.set_title()`, no
`fig.suptitle()`.

`compose_poster()` is the one deliberate exception: a **standalone** image
meant to travel on its own — LinkedIn, X, a slide, a printed handout —
where there is no surrounding HTML to hold a title, so it has to be part of
the pixels. It bakes in a serif headline + sans subtitle + mono source
line around 1-2 charts. Never use it to generate the images that go inside
an article; use it only when exporting something meant to leave the page.

Output format follows the same in-article/poster split: in-article charts
default to **SVG** (`save_fig()`'s default) — vector, so text is never
softer than the surrounding HTML at any zoom or pixel density. A poster
export is raster **PNG** instead (`save_fig(fig, path, fmt="png")`) because
social platforms and print pipelines expect a raster file, not because SVG
would look worse. The one other PNG exception is a chart with thousands of
overlapping points (dense scatter, a point-per-observation map) — SVG would
draw one element per point and bloat the file for no visual gain there.

## 7. Maps

Keep it "trivially clean," not cartographically fancy: no satellite
imagery, no terrain shading. Land is one neutral light gray/beige, water
blends into the page background (not a contrasting blue), borders are
thin white or dark-gray hairlines — the point is to let the actual data
layer (a choropleth fill, a set of colored points) be the only thing with
visual weight on the map.

## 8. Quick reference: where the code lives

| Need | Function |
|---|---|
| Call once per notebook/script | `set_style(bg="white"|"cream")` |
| Save a chart for a real article | `save_fig(fig, path)` → `.svg` |
| Save a chart with 1000s of points | `save_fig(fig, path, fmt="png")` |
| Ranking / magnitude, 1 value per category | `hlollipop(ax, labels, values, color=...)` |
| "% of X per group" (replaces a stacked bar) | `share_lollipop(labels, pct, ns, color, ...)` |
| Logistic regression vs. a binary outcome | `binned_logistic(x, y, ax, dot_color=...)` |
| Adaptive height for n categories | `lollipop_height(n)` |
| Standalone social/print export | `compose_poster([...], title=, subtitle=, source=, bg=)` |
